# SysSpy

Лёгкий детектор шпионского ПО и подозрительной активности для Linux на Python.
Это **помощник для аудита**, а не замена антивирусу/EDR: чистый Python не ловит
руткиты, прячущиеся на уровне ядра.

## Что умеет

| Модуль | Что проверяет |
|---|---|
| `процессы` | исполняемые файлы в `/tmp`, `/dev/shm`, `/var/tmp`; высокий CPU в простое; `curl\|sh` (загрузка-и-выполнение); маскировка под systemd/init; скрытые процессы (`/proc` против `psutil`) |
| `сеть` | ESTABLISHED/прослушиваемые сокеты, маппинг PID→exe, внешние соединения, подозрительные порты (4444/31337/6667…), прослушивание из временных каталогов |
| `автозагрузка` | systemd-юниты, cron (`/etc/crontab`, `/etc/cron.d`, пользовательские crontab), `.bashrc`/`.profile`/`/etc/profile.d`, autostart `.desktop` — флаг `curl`/`wget`/`nc`/`@reboot`/временных путей |
| `файлы` | real-time (через `watchdog`, опционально) + периодический скан новых/изменённых исполняемых файлов и активности во временных каталогах |
| `ввод` | процессы с fd на `/dev/input/event*` (allowlist для X/композиторов), ptrace-инъекции (`TracerPid`), подозрительные/новые модули ядра |
| `целостность` | базовая линия хешей системных бинарников и `/etc`; детект изменений/новых файлов (перехеширует только изменившиеся по mtime) |

Состояние и базовые линии хранятся в SQLite. Логируются только метаданные
(пути, PID, IP, хеши) — не содержимое файлов и не набираемый текст.

## Установка

```bash
cd SysSpy
pip install -r requirements.txt      # psutil, rich (watchdog — опционально)
pip install watchdog                 # для real-time слежения за файлами
```

## Использование

```bash
# одноразовый аудит (сохраняет находки в БД)
python3 -m sysspy scan

# непрерывный мониторинг в foreground (Ctrl-C для выхода)
sudo python3 -m sysspy watch

# инициализировать базовую линию целостности (один раз, ~1-2 мин)
sudo python3 -m sysspy baseline init
sudo python3 -m sysspy baseline check

# посмотреть последние находки / сгенерировать отчёт
python3 -m sysspy status
python3 -m sysspy report --html report.html --days 7

# полностью очистить базу данных (находки + базовые линии)
python3 -m sysspy cleandb            # спросит подтверждение
python3 -m sysspy cleandb --yes      # без подтверждения

# поставить системный сервис (требует root)
sudo python3 -m sysspy service install
sudo systemctl enable --now sysspy
```

> **Рекомендуется запускать с `sudo`.** Без прав не резолвятся PID владельцев
> чужих сокетов и не читаются `/proc/<pid>/fd` других пользователей — часть
> сетевых и кейлоггер-проверок будет неполной.

## Хранение данных

Все результаты пишутся в SQLite-файл: `~/.sysspy/sysspy.db` для пользователя
или `/var/lib/sysspy/sysspy.db` для root (переопределяется `SYSSPY_DB`/`--db`).
Там же хранятся базовые линии целостности и список виденных сетевых эндпоинтов.
Сброс = удаление файла БД (после этого `baseline init` нужно запустить заново),
либо команда `python3 -m sysspy cleandb` (очищает все таблицы, но файл оставляет).
Не коммитьте БД в репозиторий.

## Снижение ложных срабатываний

Настройки и allow/deny-списки — в `sysspy/config.py` и
`sysspy/detectors/persistence.py` / `keylogger.py`:

- `cpu_idle_threshold` — порог CPU% для флага «Высокая загрузка CPU»;
- `suspicious_ports` / `suspicious_exe_paths` / `suspicious_exts`;
- `trusted_listeners` — слушатели вроде `docker-proxy`, которым разрешён
  «подозрительный» порт;
- `TRUSTED_UNITS` — системные юниты (cloud-init, snapd, …), не считающиеся
  подозрительными;
- `INPUT_ALLOW` — процессы, легитимно читающие устройства ввода (X, compositors).

## Ограничения

- Не детектит руткиты, скрывающие процессы/модули на уровне ядра. Для этого
  используйте `unhide`, `chkrootkit`, `rkhunter` поверх SysSpy.
- Сетевая геолокация намеренно отключена (без внешних вызовов).
